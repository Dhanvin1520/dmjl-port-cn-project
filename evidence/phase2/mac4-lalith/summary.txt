  - Backup DNS "Address already in use": a copy was already running; no second instance needed.
  - 22 Nov: Jagruthi's Mac reached Mac 4 only through a ZeroTier relay (~330 ms) but DNS

    client therefore stayed on .87 until the primary was corrected. Recorded as observed.

What I learned
  A  DNS resilience: with two nameservers in /etc/resolver, clients keep resolving when the
     primary stops; the backup log proves the query really moved.
  B  TTL: a 30 s TTL means a client can keep using an old address for up to 30 s after a
     change; a manual flush removes the cached answer immediately.
  C  Backend isolation: a pf anchor can allow only the edge to reach a backend port, so
     clients must go through nginx; rolling back means flushing only our own anchor.
  D  Backend failure: nginx passive health checks route all traffic to the healthy backend and
     add the failed one back after fail_timeout; the edge itself stays a single point of failure.
  E  Edge migration: changing the DNS record moves new clients to the standby edge; cached
     clients follow once their TTL expires.
  F  Troubleshooting: checking layer by layer (DNS -> lookup -> edge port -> HTTPS -> backend
     headers -> direct backends) isolates the fault quickly; the last passing check (HTTPS 200
     but only B) and first failing check (A refused) point straight at the stopped Backend A.
     "Connection refused" means the host is reachable but no service is listening.
